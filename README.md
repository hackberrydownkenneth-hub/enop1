# エノップ 社内システム

エノップの社内システムはお互いに独立した **2 つのアプリ**で構成されています。
コード・データベース・起動ポートをすべて分けているので、片方を止めても
もう片方はそのまま動きます。

| システム | 役割 | 起動 | ポート | データベース | パッケージ |
|----------|------|------|--------|--------------|------------|
| 📊 財務・経営指標 | PL・BS の管理と毎月の経営指標(目標利益・FL 比率・客単価・現金) | `python run_finance.py` | 5001 | `enop_finance.db` | `enop_finance/` |
| 🕒 タイムカード | 打刻・勤怠集計・給与計算 | `python run.py` | 5000 | `timecard.db` | `timecard/` |

2 つのシステムは直接つながっていません。人件費だけは、タイムカードが出力する
**給与 CSV を財務システムに取り込む**形で連携します(手順は下記)。

```bash
pip install -r requirements.txt

python run_finance.py   # http://127.0.0.1:5001  経営ダッシュボード
python run.py           # http://127.0.0.1:5000  打刻・勤怠
```

# 📊 財務・経営指標システム

エノップの数字を管理するシステムです。**PL(損益計算書)・BS(貸借対照表)の入力**と、
**毎月ウォッチする経営指標のダッシュボード**を画面として分けています。

| 画面 | パス | 用途 |
|------|------|------|
| 経営ダッシュボード | `/` | 毎月の指標を見る(目標達成・売上・FL 比率・現金・推移) |
| PL・BS 入力 | `/statements` | 明細の入力と財務諸表の確認 |
| CSV 出力 | `/report.csv` | PL・BS・指標をまとめて CSV に |

## 経営ダッシュボード(自分が見る指標)

### 1. 利益と目標達成状況

エノップ開店後の目標は **毎月の計上利益(既定は営業利益)$30,000〜$50,000**。

| 指標 | 計算 |
|------|------|
| 目標判定 | 未達 / 目標達成(レンジ内)/ 目標超過 |
| 達成率 | 利益 ÷ 目標下限($30,000) |
| 不足額 | 目標下限まであといくら必要か |
| 前月比 | 前月の利益との差 |
| 年間換算 | その月の利益 × 12 |

目標は月ごとに変更でき、既定値は `ENOP_TARGET_MIN` / `ENOP_TARGET_MAX` で設定します。

### 2. 売上・客数・客単価

| 指標 | 計算 |
|------|------|
| 売上高 | PL の売上高 |
| 客数 | 手入力(月次データの入力欄) |
| 客単価 | 売上高 ÷ 客数 |
| 日商 | 売上高 ÷ 営業日数 |
| 1 日あたり客数 | 客数 ÷ 営業日数 |

### 3. 原価率・人件費率(FL 比率)

| 指標 | 計算 | 目安 |
|------|------|------|
| 原価率(F) | 売上原価 ÷ 売上高 | — |
| 人件費率(L) | 人件費 ÷ 売上高 | — |
| **FL 比率** | (売上原価 + 人件費)÷ 売上高 | 60% 以下=良好 / 65% 以下=注意 / それ超=要改善 |
| その他販管費率 | その他販管費 ÷ 売上高 | — |

### 4. 現金・損益分岐点・ランウェイ

| 指標 | 計算 |
|------|------|
| 現金残高 | 手入力。未入力なら BS の流動資産のうち「現金・預金」を含む科目の合計 |
| 月次の赤字 | 営業赤字額(黒字なら 0) |
| ランウェイ | 現金残高 ÷ 月次の赤字(黒字なら「—」) |
| 損益分岐点売上 | 固定費 ÷(1 - 変動費率) |
| 目標達成に必要な売上 | (固定費 + 目標利益)÷(1 - 変動費率) |
| 必要な日商 / 必要な客数 | 必要売上 ÷ 営業日数 / 必要売上 ÷ 客単価 |

固定費は「人件費 + その他販管費」、変動費率は「売上原価 ÷ 売上高」で計算します。

### 5. 推移

直近 12 か月の**売上高**と**営業利益**を棒グラフ(目標ラインつき)と表で表示し、
「実績のある N か月のうち何か月が目標達成か」「平均営業利益」「最高の月」を集計します。
グラフは JavaScript を使わないサーバー生成のインライン SVG です。

## PL・BS 入力

| 区分 | カテゴリ | 例 |
|------|----------|-----|
| PL | 売上高 / 売上原価 / 人件費 / その他販管費 / 営業外収益 / 営業外費用 / 法人税等 | フード売上、食材原価、家賃、支払利息 |
| BS | 流動資産 / 固定資産 / 流動負債 / 固定負債 / 純資産 | 現金預金、内装設備、買掛金、長期借入金、資本金 |

- 金額は **USD**。費用・負債・純資産もプラスの金額で入力します(区分で符号を判定)。
  内部ではセント単位の整数で保持するため、集計で丸め誤差が出ません。
- 家賃など毎月同じ科目は「前月の明細を複製」でまとめてコピーできます。
- PL は **売上総利益 → 営業利益 → 経常利益 → 当期純利益** と各利益率、
  BS は **貸借差額・運転資本・流動比率・自己資本比率**を自動計算します。
  貸借が一致しない月は画面上部に差額を警告表示します。

## 人件費の取り込み(タイムカードとの連携)

データベースを分けているため、人件費は CSV 経由で取り込みます。

1. タイムカード(`http://127.0.0.1:5000/admin`)で対象月の **CSV をダウンロード**
2. 財務システムの `/statements` で **給与 CSV を選んで「人件費として取り込む」**
3. 支給額合計(円)を `ENOP_JPY_PER_USD`(既定 150 円/$)でドルに換算し、
   PL の人件費に「CSV 取り込み」タグ付きで計上します(同月の取り込み分は置き換え)

## 環境変数

| 変数 | 既定値 | 説明 |
|------|--------|------|
| `ENOP_DB` | `enop_finance.db` | SQLite データベースのパス |
| `FINANCE_PORT` | `5001` | ポート番号 |
| `ENOP_TARGET_MIN` | `30000` | 月次目標利益の下限(USD) |
| `ENOP_TARGET_MAX` | `50000` | 月次目標利益の上限(USD) |
| `ENOP_TARGET_BASIS` | `operating` | 目標判定に使う利益(`operating`=営業利益 / `net`=当期純利益) |
| `ENOP_JPY_PER_USD` | `150` | 給与 CSV(円)を人件費(ドル)に換算するレート |
| `ENOP_TREND_MONTHS` | `12` | ダッシュボードに表示する推移の月数 |
| `ENOP_SECRET` | `dev-enop-secret` | セッション用シークレット(本番は必ず変更) |

## REST API

| メソッド | パス | 説明 |
|----------|------|------|
| `GET` | `/api/kpi?month=YYYY-MM` | 月次の経営指標と推移 |
| `GET` | `/api/statements?month=YYYY-MM` | 月次 PL・BS・目標達成状況 |
| `POST` | `/api/entries` | 明細登録 `{"month","category","item","amount","memo"}` |
| `DELETE` | `/api/entries/<id>` | 明細削除 |
| `PUT` | `/api/target` | 月次目標の変更 `{"month","target_min","target_max"}` |
| `PUT` | `/api/kpi-inputs` | 客数・営業日数・現金残高 `{"month","customers","open_days","cash_balance"}` |
| `POST` | `/api/import/payroll` | 給与 CSV の取り込み `{"month","csv"}` |

```bash
# 売上を計上
curl -X POST localhost:5001/api/entries \
     -H 'Content-Type: application/json' \
     -d '{"month":"2026-09","category":"revenue","item":"フード売上","amount":180000}'

# 今月の指標
curl 'localhost:5001/api/kpi?month=2026-09'
```

## 設計上のポイント

- **金額はセントの整数で保持** — 浮動小数点を使わず、集計時の丸め誤差を防ぎます。
- **計算ロジックの分離** — PL・BS(`calc.py`)、経営指標(`kpi.py`)、グラフ座標
  (`chart.py`)、CSV 取り込み(`payroll_import.py`)はいずれも DB・Web に依存しない
  純粋関数なので、単体テストが容易です。
- **タイムカードから独立** — パッケージ・データベース・ポートを分離し、連携は
  給与 CSV のみ。片方の不具合や停止がもう片方に波及しません。

# 🕒 タイムカードシステム

社員の出退勤・休憩を記録し、勤務時間や残業を自動集計するシンプルなタイムカードシステムです。
Python (Flask) + SQLite で動作し、Web 画面と REST API の両方を備えています。

## 主な機能

- **打刻** — 出勤 / 退勤 / 休憩開始 / 休憩終了。状態遷移を検証し、不正な打刻(未出勤での退勤など)は拒否します。
- **会社 Wi-Fi 制限** — 打刻は会社ネットワーク(許可 IP / CIDR)からのみ可能。社外からの打刻はブロックします。
- **リアルタイム表示** — 打刻画面に社員ごとの現在の状態(未出勤 / 勤務中 / 休憩中)と本日の実働時間を表示。
- **月次集計** — 社員ごとに日別の実働・休憩・残業時間を集計。中抜け(1 日複数回の出退勤)にも対応。
- **残業計算** — 所定労働時間(既定 8 時間/日)を超えた分を自動的に残業として算出。
- **一括管理・給与計算** — 管理画面で全社員の月次勤怠・給与を一覧表示。時給と残業割増から支給額を自動計算し、CSV 出力も可能。
- **REST API** — 打刻機や外部システムから利用できる JSON API。

## 会社 Wi-Fi のみで打刻できる仕組み

打刻はサーバーがリクエスト元 IP アドレスを確認し、**許可されたネットワークからのアクセスのみ**受け付けます。

- 社内 LAN にサーバーを置く場合 → LAN のサブネット(例 `192.168.10.0/24`)を許可
- クラウド運用の場合 → オフィスから出ていく固定グローバル IP(例 `203.0.113.5`)を許可

`TIMECARD_ALLOWED_NETWORKS` にカンマ区切りで設定します。未設定の場合は制限なし(どこからでも打刻可)で、画面に警告が表示されます。リバースプロキシ配下では `TIMECARD_TRUST_PROXY=1` を設定すると `X-Forwarded-For` の元 IP で判定します。

```bash
# 例: 社内 LAN と拠点の固定 IP からのみ打刻を許可
export TIMECARD_ALLOWED_NETWORKS="192.168.10.0/24,203.0.113.5"
python run.py
```

> 注: IP アドレスによる制限はサーバー側で打刻を管理する運用における標準的な手法です。社内 VPN 経由のアクセスなどは許可 IP に含まれれば通過します。より厳密な端末認証が必要な場合はクライアント証明書等との併用を検討してください。

## セットアップ

```bash
# 依存パッケージのインストール
pip install -r requirements.txt

# サーバー起動
python run.py
```

ブラウザで <http://127.0.0.1:5000> を開きます。

### 環境変数

| 変数 | 既定値 | 説明 |
|------|--------|------|
| `TIMECARD_DB` | `timecard.db` | SQLite データベースのパス |
| `HOST` | `127.0.0.1` | バインドするホスト |
| `PORT` | `5000` | ポート番号 |
| `TIMECARD_ALLOWED_NETWORKS` | (なし) | 打刻を許可するネットワーク。カンマ区切りの CIDR / IP |
| `TIMECARD_TRUST_PROXY` | `0` | `1` にするとプロキシの `X-Forwarded-For` で IP 判定 |
| `TIMECARD_OVERTIME_RATE` | `1.25` | 残業割増率 |
| `TIMECARD_SECRET` | `dev-timecard-secret` | セッション用シークレット(本番は必ず変更) |

## 使い方(Web UI)

1. トップ画面下部のフォームから社員(社員コード・氏名)を登録します。
2. 各社員カードのボタンで打刻します。状態に応じて押せるボタンが自動で切り替わります。
   - 未出勤 → **出勤**
   - 勤務中 → **休憩開始** / **退勤**
   - 休憩中 → **休憩終了**
3. 社員名をクリックすると、月次の勤怠集計と打刻履歴を確認できます。

## REST API

| メソッド | パス | 説明 |
|----------|------|------|
| `GET`  | `/api/employees` | 社員一覧と現在の状態 |
| `POST` | `/api/employees` | 社員登録 `{"code","name","hourly_wage"}` |
| `PATCH`| `/api/employees/<id>` | 時給変更 `{"hourly_wage"}` |
| `POST` | `/api/employees/<id>/punch` | 打刻 `{"punch_type"}` (`in`/`out`/`break_in`/`break_out`)。会社ネットワーク外は 403 |
| `GET`  | `/api/employees/<id>/summary?date=YYYY-MM-DD` | 指定日の勤怠集計 |
| `GET`  | `/api/payroll?month=YYYY-MM` | 全社員の月次給与レポート |

画面: `/`(打刻)、`/employee/<id>`(社員別 月次勤怠・給与)、`/admin`(一括管理・給与計算)、`/admin/payroll.csv`(CSV 出力)

`/admin/payroll.csv` は財務・経営指標システムの人件費取り込みにそのまま使えます。

### 例

```bash
# 社員登録
curl -X POST localhost:5000/api/employees \
     -H 'Content-Type: application/json' \
     -d '{"code":"E001","name":"山田太郎"}'

# 出勤打刻
curl -X POST localhost:5000/api/employees/1/punch \
     -H 'Content-Type: application/json' \
     -d '{"punch_type":"in"}'

# 本日の集計を取得
curl localhost:5000/api/employees/1/summary
```

## 設計上のポイント

- **計算ロジックの分離** — 勤務時間・残業の計算は `attendance.py` に純粋関数として実装。
  データベースや Web フレームワークに依存しないため、単体テストが容易です。
- **状態遷移の検証** — 直近の打刻から現在の状態を判定し、不正な打刻を防ぎます。
- **データ整合性** — 退勤打刻漏れなど区間が閉じていない場合は警告(`warnings`)として表示します。
